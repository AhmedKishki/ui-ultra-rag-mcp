# AGENTS.md

This repository owns reusable local UI infrastructure for UltraRAG-derived MCP servers. It is not an MCP server and must not acquire retrieval, ingestion, or storage behavior of its own.

## Boundaries

- Keep the package independent of FastMCP and UltraRAG internals.
- Keep server-specific MCP transport, command-line arguments, paths, validation, and lifecycle in a consuming repository's adapter.
- Never inspect or mutate a server's corpus, chunks, indexes, or metadata directly.
- Serve only on loopback addresses unless a complete authenticated remote security design is explicitly requested.
- Keep writes same-origin and JSON-only.
- Treat `SourceFile` as an adapter authorization decision; do not add generic filesystem path resolution here.
- Do not add answer generation or chatbot behavior. The workspace displays evidence returned by the adapter.
- Keep the interface basic, readable, keyboard accessible, and dependency-free in the browser.
- Retain the UltraRAG credit and independent-project disclaimer in `README.md` and `NOTICE`.

## Public package contract

- `UIProfile` supplies labels and supported capabilities, including the optional `version_label` the header shows under the project name.
- `UIAdapter` normalizes one server to the document-workspace operations.
- Portable bundle buttons only forward `export_bundle` and `import_bundle`; archive placement, validation, and storage remain adapter/server concerns.
- `source_selection`, `category_partitions`, `project_metadata`, and `bibliographic_filters` are opt-in and default to `False`: they only forward `source_ids`, `exclude_source_ids`, `categories_any`, `projects`, `projects_any`, `authors_any`, `titles_any`, and `languages_any`, and the partition, project, and language lists are read from the status response's `categories`, `projects`, and `languages` entries. Never derive partitions, project tags, or languages from source metadata in this repository, and keep a request carrying a disabled filter field a 400 rather than a forwarded call. `languages_any` rides on `bibliographic_filters` because a source's language is recorded beside its authors and its title, so one flag governs all three and an adapter that declares the flag has declared the layer. A field this repository sends as an empty list when a reader typed nothing is absent from a request body, so adding a gated field does not change what a pinned adapter receives until a reader uses the control.
- `memory` and `memory_writes` are opt-in and default to `False`: the Memory view, its routes, and the write controls appear only for an adapter that reports both. Never invent a memory scope, interpret one, or resolve a memory path here; a scope is an opaque adapter-supplied identifier whose label and directory arrive in the `memory_status` response. The view renders every scope the status reports, local and global together, and sends a write back only to the scope whose block it came from. The `memory_standing_save` request forwards only the digest the page read, and the adapter owns the comparison and the refusal.
- `documents` defaults to `True` and is turned off by an adapter that serves no corpus: the document workspace, the `search` route, and the status summary are then hidden, while `status` and `health` stay available because the header shows the identity they carry.
- `create_ui_app` builds the Starlette application.
- `clients` is opt-in and defaults to `False`: a host that is not a server has no client to report, so the panel, the panel's two routes, and the 501 for a host that advertises the flag without the methods are all decided here rather than in each consumer. The two adapter methods live on a `ClientControl` protocol separate from `UIAdapter`, because a host that serves a workspace is not thereby a server. Never let this library name, interpret, or end a client: the adapter supplies the list and performs the disconnect, and the reason it passes along is a sentence the UI shows unchanged.
- `generations` is opt-in and defaults to `False`. The listing arrives in the status response's `generations` entries, so the panel needs no read route; the only operation is `remove_generation`, which takes `generation_id` and a `confirm` that repeats it. A missing or mismatched `confirm` is a 400 before the adapter is called, because a workspace that supplied its own confirmation would be a workspace where one click removed a generation nobody chose. Render the generation the host reports as current with no remove action, rather than with one that would be refused, and keep the typed id a gate on the submit button rather than a message beside it.
- `sql_console` is opt-in and defaults to `False`: this library cannot know which store an adapter keeps, so it never opens one and offers the panel only to a host that declares the flag. The scopes arrive in the status response's `sql_scopes` entries, so the panel needs no read route, and a host that reports no scope gets the controls disabled rather than an empty select. The two adapter methods live on a `SqlConsole` protocol separate from `UIAdapter`, because a statement is not a document operation, and a host that advertises the flag without them is refused with a 501. The statement is forwarded exactly as typed while the scope is trimmed, a missing or empty field is a 400 before the adapter is called, and a statement past 20000 characters is refused here so an accidental paste cannot reach the store. The panel states that execute changes stored records and that the server reindexes the change, because nothing here can undo it.
- `settings` is opt-in and defaults to `False`. The panel lists what the server reports through `settings_read` and sends a change through `settings_write` with `values`, the `expected_revision` the page loaded, and a `confirm`; the reply's `revision`, `changed`, `requires_ingest`, and `message` are read as they arrive and nothing is invented. Never name a setting, supply a range or a list of choices, or default a missing value here: which settings exist, where each came from, and what changing one costs are the server's facts, and a refusal is shown unchanged and never retried. A row shows the key's label, the `doc` the server sent, the value the page loaded, the `origin`, the `cost.message`, the `env` variable that would override the value, and the control, and every one of those keys is optional: a host that sends none renders the row it always did. `choices` draws a select over exactly the values the server offered, `bool` a checkbox, `minimum` and `maximum` become the bounds on a number field, and a value reported with no value loads an empty control, because an empty control the page loaded is not a change to send. A value the server reports unwritable is shown disabled with its origin named. The workspace sends only the keys whose value differs from what the page loaded, and a key that costs a regeneration or a model change is confirmed by typing `ingest` or `model` first; the workspace says that an ingestion is needed and does not start one.
- `chunk_exclusion` is opt-in and defaults to `False`. A search hit and a passage in the context dialog each offer excluding or restoring one chunk, and the server's own listing from `list_chunk_exclusions` is shown beside the status with a restore for each row; `set_chunk_inclusion` takes `chunk_id`, `included`, and a `reason` for an exclusion and no reason for a restore. The existing whole-source exclusion is a separate control and is untouched. The workspace names no chunk, resolves no chunk id, and decides nothing about a chunk the server did not report: an entry the server marks as absent from the current generation is labelled with the wording it supplied or with a fixed sentence, and a refusal keeps the dialog open with its own message.
- `projects` is opt-in and defaults to `False`. `list_projects` answers the selector at the top of the sidebar, and its `projects`, `current`, and `message` are forwarded whole: which projects exist, which one this page serves, and whether an app is up for one are the host's facts, and a project with no app has no address, so nothing here invents one. Selecting a project never repoints this page at it; the reader is offered that project's own workspace, and a project with no app is offered the command that starts it, taken from `UIProfile.project_start_command` because a command this repository composed would be one the reader could paste and fail on.
- `agent_entry` is opt-in and defaults to `False`, and `UIProfile.project_start_command` is empty until a host fills it in. `agent_entry` returns the host's own client entry text, which is shown and copied unchanged; a second generator here would be a second place for a client's configuration to be wrong.
- The sidebar is the whole navigation: `Search`, `Sources`, `Config`, `MCP`, and `Memory`, one nav item per panel, each carrying the capability that decides whether its panel exists. The column sits beside the workspace at 992px and wider and becomes a drawer behind a header button below it, closing on Escape without trapping focus. The item in view is marked `aria-current="page"` rather than with a tab role, carries an inline SVG icon and nothing that must be fetched, and the project name is repeated as a quiet footer beneath the views. A sidebar holding no item is removed with them, and a profile that leaves no item shows no panel rather than the panel of an item that is gone.
- The project selector is the first thing in the sidebar and above the views, because changing the workspace is what a reader reaches for before choosing a view. The header carries the project's identity and the actions, and not the control that changes it. The selector rides into the drawer below 992px rather than being duplicated for it.
- Space is a declared scale, not a value typed into each rule: spacing and type custom properties live in the `:root` block of `app.css` and every gap, pad, margin, and size is one of them. Body text reads at 1.5 and a long description higher than that, prose and settings text carry a max readable width, and a settings row wraps rather than truncates. The palette is cream and burnt orange, after Anthropic's own: a warm paper ground, warm greys rather than neutral ones, near-black and warm-black text, and one burnt-orange accent. UltraRAG's geometry is the vocabulary rather than its palette, so the 6/12/16 radii, its three shadows, `Inter` for the interface and `JetBrains Mono` for code, and the 576 / 768 / 992 breakpoints are its own, while the accent stays far from its accent green `#10a37f` and its accent blue `#2563eb` because borrowing either would imply a product relationship this package does not have. `Inter` and `JetBrains Mono` are named with system fallbacks and never downloaded, and no dependency, font file, or external request may be added.
- Both colour schemes name the same tokens, and every pair that carries text or the focus ring meets WCAG AA: body text, labels, the secondary and tertiary levels, the accent on a card and under its own fill, the danger and warning pairs, and the focus ring against the card, the surface, the sidebar, and the input fill. The ratios are computed by `tests/test_ui.py` rather than trusted, because the light accent is darkened to `#b8592f` for white text and the tertiary to `#676458` for the cream surface, and both choices exist only because the pairs they serve fail at the values that read better.
- Printing serves the sources and passage views, which people print to transcribe: the sidebar, the header, the search console, the status summary, the transient toasts, and the dialogs do not print, and the passages keep their line breaks.
- `run_ui` starts Uvicorn on a loopback address.

Changing operation names, payloads, capability names, or public routes is an API change. Preserve compatibility or release a new major version. A flag that hides an existing control defaults to `True`, so it stays inert for a pinned adapter; a flag that adds a control the adapter has to honour, as the filter flags do, defaults to `False` and stays invisible until an adapter asks for it. `footer_text` defaults to empty: the UI states no policy of its own, and the quotation rule belongs in the server's documentation and its tool descriptions.

## Validation

Before committing:

```bash
uv lock --check
uv run ruff format --check .
uv run ruff check .
uv run pytest -q
uv run python -m compileall -q src tests
```

Tests must cover packaged static assets, the normalized routes, capability enforcement, same-origin write protection, the memory view and its writes, the SQL console and its writes, and source-file delegation.
